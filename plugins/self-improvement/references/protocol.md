# Evidence-gated convention repair

1. **Detect and gate.** Name two or more concrete recurrence sites and at least one measured
   result, execution log, source file:line, or reproduction. One-off: local record only.
   Missing evidence: verify or mark needs verification. Frozen artifact: report the needed
   escalation. Existing authorization and project constraints remain in force.
2. **Classify.** New / correction / clarification / dead rule / reusable procedure.
   Dead rules use $self-improvement:si-archive. A reusable Codex procedure can become a scoped skill after
   checking existing skills; do not create .claude/agents files for Codex.
3. **Verify.** Check the actual index or format-map equivalent, then search head and archive
   for duplicates. Read only relevant bodies. Reconcile contradictions in one canonical
   location. If enforcement can be expressed in an existing tool, try a small rule proof
   of concept and keep only the unenforceable judgment in prose. Distinguish configured
   behavior from observed execution. For performance, record run conditions and cold/cache
   state; repeated warm runs cannot establish the original problem was fixed.
4. **Codify.** Follow runtime.md and the actual routing map. Shared text stays shared;
   Codex-only instructions have explicit runtime scope. Choose the form below and make
   the smallest evidence-backed edit. Wire obligations/caps into the step that executes
   them, not just a preamble.

| Failure | Useful form |
| --- | --- |
| Known rule skipped under pressure | Clear prohibition with rationale and observable red flags |
| Wrong output shape | Recipe with the intended components and order |
| Missing element | Required slot in the existing template/checklist |
| Conditional behavior | Separate conditional on an observable fact |

Judgment rules need conditions and counterexamples. Narrowing scope needs evidence too.
Scope applicability structurally; put a genuine exception in a separate conditional rather
than a vague escape clause. Do not generalize these wording choices into unrelated tasks.

Before propagation, re-judge both the incident and valid counterexamples with the proposed
wording. Fix ambiguous wording first. For an expensive or contested behavior rule, an
authorized independent evaluation should include three scenario runs and a no-rule control.
If delegation or the required evidence is unavailable, report that limitation and keep the
candidate provisional. Do not invent measured effectiveness or silently require extra
agents for ordinary edits.

5. **Propagate.** Find existing violations. Repair and verify those within the authorized
   work; otherwise list the remaining targets. A changed template needs idempotent
   propagation and an expected/actual edit count. Update existing checklists when they own
   the completion criterion.
6. **Record and measure.** Follow data.md: one log block for this work, one index entry per
   codification, real destinations, evidence and verification. Count actual body blocks and
   rotate oldest overflow through $self-improvement:si-archive when an archive is configured.

Report the project's existing self-improvement marker, or `self-improvement: N items + where`
/ `self-improvement: none`. Count codifications, not rejected/local candidates.
