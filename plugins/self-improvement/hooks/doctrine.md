# Self-improvement in Codex

These instructions apply only to Codex.

1. When a missing, wrong, or ambiguous convention costs you during an authorized task, repair the convention in that unit of work if it is evidenced and recurs at two or more named sites. A one-off belongs in the task's local record; a guess needs verification. Respect frozen artifacts and the user's scope and permissions.
2. Use $self-improvement:si-improve for the repair protocol, $self-improvement:si-init when no convention system is registered, and $self-improvement:si-archive for over-budget documents or specifically identified dead/duplicate clauses.
3. Use one existing project data file and its real format. Do not start another changelog for Codex or replace a Claude-generated data file's records or version stamp.
4. Put enforceable rules in tools first. Shared judgments belong in shared project docs; Codex instructions belong in the relevant AGENTS.md (or existing AGENTS.override.md). Claude instructions belong in CLAUDE.md or .claude/rules and do not govern Codex.
5. Before finishing a unit of work, ask once what convention gap will recur. Report "self-improvement: N items + where" or "self-improvement: none", using the project's existing marker/language when present. This is an instruction, not a Stop gate.
6. Draft directly when routing is unclear. Optional independent drafting uses the bundled convention-smith reference only when delegation is available and authorized; no Claude agent or tool name is assumed.
